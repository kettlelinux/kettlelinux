A public test build for the AYN Odin 2 Portal. It runs from a microSD card; Android on the internal storage is not touched.

## What's in it
- Game Mode with Valve's arm64 Steam client, and a Plasma desktop
- The Plasma desktop inside Game Mode as well, from Desktop in Steam's library
- Atomic A/B updates from Steam's own Check for updates, with automatic fallback if an update fails to boot
- Starts through the U-Boot AYN ships on the device: no bootloader swap
- Kettle Installer: install to the internal storage next to Android, with a backup of the internal storage first
- Game Settings: everything set per game in one place, with tabs: FEX, DXVK, vkd3d, Turnip and Proton settings (shared with other players), power and refresh rate, upscaling and frame generation (off until enabled per game), and .NET games run natively on ARM64
- Power control from Steam's Performance panel: TDP, performance profiles, GPU clock and per-game fan curves
- Epic Games, GOG, Amazon Games and Flathub's ARM64 apps in Game Mode, through Game Stores
- Device Settings: battery charge limit and charge speed, lights, the screen's refresh rate, and system settings (start-up mode, SSH, factory reset)
- Gyro and accelerometer for Steam Input
- Lights: the rings around the sticks and the light by the power button
- Crash reports in Quick Access, which you can share to report a crash on GitHub
- Android games in Steam, through Lepton, the Android layer Valve made for the Steam Frame
- Windows games outside Steam: Wine with FEX, DXVK and vkd3d-proton, plus Lutris and Heroic
- GE-Proton and Proton-CachyOS, and emulators and streaming apps from Flathub, installed from Kettle Welcome
- Hardware video decoding in Firefox (H.264, HEVC, VP9 and AV1), YouTube included
- A microSD card you put in becomes a Steam library, as on a Steam Deck
- Back buttons M1 and M2

## Changes
- Sleep: a power line that feeds the internal storage now stays on while asleep. This may fix the storage occasionally failing after waking up.
- The microphone: a fix for how its stream is reopened after sleep.
- The fan's temperature sensors no longer check every 10 ms when warm, so the device wakes up less.
- The charge limit holds while asleep: a battery already at the limit stays there through sleep, and one below it keeps charging.
- The power service is sturdier: a damaged settings file no longer stops it, one failing part (fan, TDP, Auto TDP, charging) no longer stops the others, and a custom fan curve no longer keeps the GPU from throttling itself. It also wakes up less often when idle.
- Security fixes from a code review: a program running as you, a game included, can no longer get root access through Decky's plugins, a settings reset or a crafted SD card label. SD cards are mounted without device files or setuid programs, and only the built-in volume keys can confirm a reset or SSH (a Bluetooth remote could before).
- Android games: a crafted APK can no longer write outside its own game folder.
- Game Settings no longer loses a change made while another was being saved, and puts a game's launch options back if saving fails. Frame generation's frame rate readings now work for games from Game Stores.
- Game Stores: reinstalling a game reuses its Steam shortcut instead of adding a second one, and uninstalling one also removes its Game Settings, Frame Gen and upscaling settings.
- Upscaling: SGSR 2 and Arm ASR fixes.
- Native ARM64 games fall back to running under FEX if anything goes wrong, instead of failing to start.
- MangoHud no longer counts a connected controller's battery (DualSense, DualShock 4) as the device's.
- On-screen keyboard: fixes for text selection and the cursor position.

## Known issues
- Hardware video decoding in Firefox is new. If a video stops, or plays sound over a still picture, please open an issue.
- Android games: Android's status and navigation bars show, and can cover buttons in some games. Games that need Google Play services or buy things through Google Play inside the game don't work, and neither do games made only for x86 or for Android 12 and newer.
- Early build: some features have not been tested on a Portal yet.
- Steam Remote Play's hardware decoding is new: if a stream shows a green or black picture, please open an issue.
