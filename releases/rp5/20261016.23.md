A public test build for the Retroid Pocket 5, Kettle's first device with a Snapdragon 865. It runs from a microSD card; Android on the internal storage is not touched.

Starting it from the card needs Retroid's U-Boot, flashed once to the loader partition from a PC, or ROCKNIX's ABL if you already have it. Follow the RP5 install guide: https://github.com/kettlelinux/kettlelinux/blob/main/docs/INSTALL-RP5.md

## What's in it
- Game Mode with Valve's arm64 Steam client, and a Plasma desktop
- The Plasma desktop inside Game Mode as well, from Desktop in Steam's library
- Atomic A/B updates from Steam's own Check for updates, with automatic fallback if an update fails to boot
- Kettle Installer: install to the internal storage next to Android, with a backup of the internal storage first
- Game Settings: everything set per game in one place, with tabs: FEX, DXVK, vkd3d, Turnip and Proton settings (shared with other players), power and refresh rate, upscaling and frame generation (off until enabled per game), and .NET games run natively on ARM64
- Power control from Steam's Performance panel, and a GPU overclock up to 750 MHz as Steam's manual GPU clock, per game
- Epic Games, GOG, Amazon Games and Flathub's ARM64 apps in Game Mode, through Game Stores
- Device Settings: battery charge limit and charge speed, lights, and system settings (start-up mode, SSH, factory reset)
- Lights: the rings around the sticks
- Crash reports in Quick Access, which you can share to report a crash on GitHub
- GE-Proton and Proton-CachyOS, and emulators and streaming apps from Flathub, installed from Kettle Welcome
- A microSD card you put in becomes a Steam library, as on a Steam Deck

## Changes
- Frame generation on the RP5's single 60 Hz screen runs at 60 Hz, not 50.
- Controller fixes: garbled reports from the controller chip are ignored, and the chip is powered off in sleep.
- Auto TDP is on by default: games run on the lowest CPU and GPU clocks that still hold Steam's frame rate limit, for longer battery life. It now gets Steam's real frame limit, holds a game at the frame rate it actually reaches when that's below the limit, lowers the CPU when the GPU is what holds a game back, gives a busy GPU its clock back first, and ignores loading screens. Turn it off per game or for all games in Game Settings > Perf.
- Steam's TDP limit applies again, and a custom fan curve handed back to the device no longer leaves the fan at full speed.
- Games load gamescope's own Vulkan layer, so Steam's frame rate limit holds in every game.
- Game Settings: options to turn off Lumen and fix Nanite in Unreal Engine 5 games, an Unreal graphics API choice, lifting Steam's 4 GB video memory limit for a game, and Turnip from upstream Mesa as a per-game choice next to Valve's. Path of Exile 2 starts in DirectX 12, Titan Quest II's THQ Nordic overlay is turned off, and a lower render resolution now suggests the Linear filter.
- Games see 4 GB of video memory, as Valve intended, and the shader cache is 4 GB.
- Baldur's Gate 3's pinned threads move off the slow cores, and background services stay off the fastest core.
- Less CPU use at idle: the controller service and the Decky plugins' backends sleep until something changes. The controller service is InputPlumber 0.82.
- .NET 10.0.13 (a security release) for native .NET games, a newer vkd3d-proton with fixes for Ace Combat 8, NBA 2K27 and Tracing Decay, and Android games no longer hang when a game won't close.
- The Kettle Installer's progress window stays open until it's finished.

## Known issues
- Early build. Checked on an RP5: starting from the SD card through U-Boot, the screen, GPU and Vulkan, the gamepad, touchscreen, speakers, Wi-Fi, Bluetooth, the microSD card at full speed, and the GPU overclock in a game.
- Newer RP5s have a different screen (Visionox). If the screen stays black, put an empty file named visionox on the card's KETTLE partition from a PC, as the install guide shows. Not tested on a Visionox RP5 yet.
- Not tested yet: starting from ROCKNIX's ABL, installing to the internal storage, sleep (fixes are in, testing goes on), rumble, headphones and DisplayPort audio, and power settings on battery.
- The charger's readings (input current) are not accurate.
